----------------------------------- Layers in Docker ---------------------------------------


In Docker, layers are fundamental part of the image architecture that allows docker to be efficent, fast, and 
portable. A docker image is essentially built up from a series of layers, each representing a set of differences 
from the previous layer.    


How layers are made : 

1. Base Layer: The starting point of image, typically an operating system like Ubuntu, Alpine or any other base 
image specified in a DockerFile 

2. Instruction Layers : Each command in a DockerFile creates a new layer in the image. These include Instruction
like RUN, COPY, which modify the filesystem by installing packages, copying files from host to container, or other
changes.

3. Reusable & Sharable : Layers are cached and reusable across different imagess, which makes building and sharing
images more efficent. If multiple images are built from the same base image or share common instruction, they can 
reuse the same layers, reducing storage space and speeding up image downloads and builds. 

4. Immutable : Once a layer is created, it cannot be changed. If a change is made, Docker creates a new layer that 
captures the difference. This immutability is key to Docker's reliablity and performance, as unchanged layers can be
shared acroos images and containers.

-------------------------------------- Networks and Volumes -----------------------------------------------------

Networks and Volumes are concepts that become important when you have multiple containers running in which you
1. Need to persist data across docker restarts - Volumes
2. Need to allow container to talk each other - Networks

--------------- Volumes -----------------

If you restart a mongo docker container, you will notice that your data goes away. 
This is because docker container are transitory (they don't retain data across restarts)


-- steps

1. Create a volume:
```
docker volume create name_of_volume
```

2. Mount the folder in mongo which actually store the data to this volume:
```
docker run -v name_of_volume:/data/db -p 27017:27017 mongo
```

3. Open mongocompass and add some data to it:

4. now it you kill the container, still the data will be in volumne
you can connect next container with that volume, data will be there.

or if you stop/start container, the data still be there.



---------- Networks ------------------


In Docker, a network is a powerful feature  that allows container to communicate with each other and with the 
outside world(host machine).

Docker containers can't talk to each other by default.

localhost on docker container means it's own network and not the nework of the host machine.
