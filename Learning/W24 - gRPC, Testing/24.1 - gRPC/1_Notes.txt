
--------------------------------- What is RPC ----------------------------------------------

RPC stands for remote procedure call. As the name suggests, it lets you call a function in on a different process/
server/backend and get back the response from it. 



------- Why RPC --------
This is how we've made our backends talk to each other until now. 

We send out an http request, get back a response. 

There are few flaws in this approach: 
1. No Types : You dont know the shape of data you will get back. You might be able to share types between 2 Node.js
backends somehow, but if other backend is in Rust, then you cant get back the types from it. 

2. We use JSON to serialize and deserialize the data. 

3. We have to know what axios is, or what fetch is. We need to understand HTTP and how to call it. 

4. Not language agnostic at all. We have to use a different library in Java, Go, Rust to send an http request
to the server.

---------------------------------------- Proto Buffs -------------------------------------------------------------

Ref: https://protobuf.dev/

Protocol Buffers are google's language - neutral, platform-neutral, extensible mechanism for serializing 
structured data, think XML, JSON.

The protocol buffers are where we define our service definitions and messages. This will be like contract or 
common interface between the client and server on what to expect from each other; the methods, types and returns
of what each operation would bear.

1. Schema Definition Language: Protocol Buffers use a Schema definition language (.proto files) to define the 
structure of data. 

2. Binary serialization : Protocol Buffers serialize the data into the binary format, which is more compact 
and efficient compared to text-based formats like XML and JSON. 

3. Language Support and Code generation: It support code generation for a wide range of programming languages based
on your .proto files. 


Let's create a simple proto file: 

- message.proto: 
```
syntax = "proto3";

message Person {
  string name = 1;
  int32 age = 2;
}

service PersonService {

  //add person to address book
  rpc AddPerson(Person) returns (Person);

  //get person from their name
  rpc GetPersonByName(GetPersonByNameRequest) returns (Person);

}

message GetPersonByNameRequest {
  string name = 1;
}
```


There are few things to unpack here - 

- message : A message that can be encoded/decoded/transferred.
- types: string, int32
- service: Describe what all rpc methods you support.
- Field Numbers: 
  In protocol buffers, each field within a message type is assigned a unique numerical identifier called a tag or
  field number. These field number servs different purposes: 

  1. Efficient encoding:Field numbers are used instead of field names in the binary encoding, making the message 
  size smaller and parsing faster. Smaller numbers (1–15) are encoded more compactly than larger ones.

  2. Backward Compatibility:Because each field has a unique number, old software can safely ignore unknown fields 
  with unrecognized numbers. This allows newer versions of a message to add fields without breaking existing 
  implementations.

  3. Language Independence:Field numbers provide a consistent reference across different programming languages. 
  Even when names or structures change between languages or versions, the field numbers remain the same for 
  identification and mapping.

```
import protobuf from "protobufjs";

async function run() {
  const root = await protobuf.load("a.proto");
  const User = root.lookupType("User");

  const payload = { name: "Vishnu", age: 24, email: "vishnu@example.com" };

  const errMsg = User.verify(payload);
  if (errMsg) throw new Error(errMsg);

  const message = User.create(payload);
  const buffer = User.encode(message).finish();
  console.log("Serialized Buffer:", buffer);

  // here, either store, or send the data..

  const decoded = User.decode(buffer);
  console.log("Deserialized Object:", decoded);
}

run().catch(console.error);
```

-------------- Types in pbf (protobuf) -----------------------

1. Scalar types: 
    - int32, int64, uint32, uint64, 
    - float, double
    - bool 
    - string 
    - bytes 



    ```
    syntax = "proto3"

    message Address {
      string street = 1;
      string city = 2;
    }

    message Person {
      string name = 1;
      Address address = 2;
    }
    ```


2. Message Types: 
    - Message types allow you to define structured data with nested feilds, they can contain scalar types, other 
    messages types or repeated types(array).

    ```
    message Person{
      string name = 1;
      repeated string phone_num = 2;  // now it can have array of phone_numbers. 
    }
    ```

3. Enum Types: 

    ```
    enum PhoneType {
      MOBILE = 0;
      HOME = 1;
      WORK = 2;
    }
    ```


4. Maps 

    ```
    message MapMessage {
      map<string, int32> id_to_age = 1;
    }
    ```

--------- Creating a JSON RPC server --------------------

see rpc-implementation folder for details code in typescirpt. below is in Javascript.

```
const express = require('express');
const bodyParser = require('body-parser');

const app = express();
app.use(bodyParser.json());

// Example method handlers
const methods = {
  add: ({ a, b }) => a + b,
  subtract: ({ a, b }) => a - b,
};

// JSON-RPC route
app.post('/rpc', (req, res) => {
  const { jsonrpc, method, params, id } = req.body;

  if (jsonrpc !== '2.0') {
    return res.json({ jsonrpc: '2.0', error: { code: -32600, message: 'Invalid Request' }, id });
  }

  const handler = methods[method];

  if (!handler) {
    return res.json({ jsonrpc: '2.0', error: { code: -32601, message: 'Method not found' }, id });
  }

  try {
    const result = handler(params);
    res.json({ jsonrpc: '2.0', result, id });
  } catch (error) {
    res.json({ jsonrpc: '2.0', error: { code: -32603, message: error.message }, id });
  }
});

// Start server
const PORT = 3000;
app.listen(PORT, () => {
  console.log(`JSON-RPC server running on http://localhost:${PORT}/rpc`);
});

```
